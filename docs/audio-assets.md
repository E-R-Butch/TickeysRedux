## Provenance evidence and replacement decision

The three download notices match the corresponding files in [yingDev/Tickeys commit `da238a94bec6545730571e59546aae535b2b69f1`](https://github.com/yingDev/Tickeys/tree/da238a94bec6545730571e59546aae535b2b69f1/Tickeys.app/Contents/Resources/data) byte-for-byte. The local import is commit `8e14d2a831933223a264ff2a2a05476c2335e962`. Each retained WAV was compared with its same-named upstream WAV: all 21 have the same frame count and sample rate. After channel averaging, waveform correlation is at least 0.9996 (at least 0.9999998 except `bubble/enter.wav`), consistent with inherited gain/channel processing. This establishes the chain to the pack notices; it does not reconstruct undocumented historic edits.

The local import, upstream resource tree, and bounded search did not establish separate recording licenses for the five replaced packs. A repository-wide MIT file alone was not treated as evidence that third-party recordings could be relicensed. Those WAVs are absent from the current resource tree after replacement. Earlier commits/releases are unchanged. No audio files were found under `legacy/`; packaging uses `assets/data/`, not `legacy/`.

## Synthetic pack generation

[`scripts/generate_audio_assets.py`](../scripts/generate_audio_assets.py) uses Python's standard library only, with no network calls or recording inputs. The script and newly generated WAVs use the [project MIT license](../LICENSE), reproduced in each synthetic pack's `license.txt`. That declaration does not apply retroactively to removed recordings.

- Format: uncompressed PCM, signed 16-bit little-endian, mono, **44,100 Hz**.
- Determinism: base seed **`0x5449434B`**, XORed with the first four SHA-256 bytes of `scheme_id/file.wav`, interpreted little-endian. Explicit xorshift32 supplies noise. Each file's actual seed is in the manifest.
- A 44-frame attack fade and 441-frame end fade eliminate boundary discontinuities. DC removal uses the same envelope. Peak normalization targets **0.55 full scale**, quantized to **18,022 / 32,767**, about **−5.2 dBFS**. This is a per-file peak, not a limit on the application's mixed output.
- `Synth Click`: high-passed noise, damped 1,850/820 Hz resonances, and a second 2,350 Hz tap; 110 ms.
- `Synth Thock`: damped 235/470 Hz resonances, low-passed noise, and a softer return tap; 140–200 ms.
- `Synth Typewriter`: noise attack and 690/2,110 Hz resonances, a delayed mechanism tap, extra scroll taps, and a 1,568/3,136 Hz return bell; 160–400 ms.
- `Synth Blades`: filtered-noise swish and inharmonic 1,390/2,377/3,551 Hz resonances; 210–270 ms.
- `Synth Space`: two downward frequency sweeps with 71 Hz phase modulation; 200 ms.
- Frequency variation is deterministic (0.94–1.06 times nominal). Enter/space variants have longer clip durations where their filenames identify those keys.

The synthesis uses platform `math` functions; byte equality is checked on the build platform rather than promised across every possible math-library implementation.

## Inventory and verification

[`assets/data/audio-manifest.json`](../assets/data/audio-manifest.json) enumerates every distributed WAV, source/license, SHA-256, channels, sample rate, frames, duration, peak and synthetic seed. It is shipped in the App Bundle. Full CC texts in `assets/data/licenses/` come from the official [CC BY 3.0 text](https://creativecommons.org/licenses/by/3.0/legalcode.txt) and [CC0 1.0 text](https://creativecommons.org/publicdomain/zero/1.0/legalcode.txt). Existing per-pack credits are preserved unchanged.

```sh
# Regenerate only the 32 synthetic WAVs, then inventory all 53 WAVs.
python3 scripts/generate_audio_assets.py
# Read-only check of generated bytes, manifest, mappings and WAV coverage.
python3 scripts/generate_audio_assets.py --check
```

The read-only check fails on missing/extra WAVs, invalid mappings, changed generated bytes, or manifest drift. Decoder testing and subjective listening are separate checks; valid PCM does not establish playback through a user's actual output device.
