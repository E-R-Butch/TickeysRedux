# Bundled dependency license sources

`dependencies.json` and `dependencies/` are generated by
`python3 scripts/generate_notices.py`. The script uses the offline Cargo graph for
`aarch64-apple-darwin`, follows normal and build dependencies, verifies each cached
`.crate` archive against Cargo.lock, and preserves all license/NOTICE files it
finds, including nested third-party notices. It checks copied source files against
the verified archive rather than relying on their filenames alone.

Seven locked crates omit their license files from the published crate archives.
`upstream/sources.json` pins supplemental material to the crate's
`.cargo_vcs_info.json` source revision. Source URLs, SHA-256 hashes, package
versions, license expressions and upstream crate paths are recorded there.

The three objc2 source revisions supply only a `LICENSE.md` declaration linking
the official license terms. Their declarations and the linked official terms
are included unchanged, with HTML markup removed from the MIT and Zlib web pages.
The extraction is described in `sources.json`. These are references to the
declared terms, not newly created copyright grants. No absent copyright holder or
year is filled in. The Zlib reference retains the linked page's own attribution;
that attribution is not a claim about the authors of the objc2 crates. The
generated `SOURCE-NOTICE.txt` files explain these distinctions and preserve any
authors declared in the individual Cargo packages.

`--check` validates all pinned upstream hashes, source provenance and generated
files without writing or making network requests. Missing source material,
changed upstream revision, altered source files, unexpected generated files, or
changes to the resolved dependency graph cause the check to fail. When a locked
dependency is upgraded, review its license sources before regenerating; the
script does not substitute a generic license for missing material.

Rust sysroot/runtime notices are copied by the application packager from the
actual build toolchain into `licenses/rust-runtime/` inside the application.
They are not part of the Cargo dependency manifest. Sound-asset licenses are
stored alongside the assets and documented separately in `docs/audio-assets.md`.
